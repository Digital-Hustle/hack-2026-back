# Безопасность реализации

JWT проверяется только на Gateway. Подробности: docs/GATEWAY_AUTH.md и `.agents/skills/cashflow-architecture/references/gateway-and-patterns.md` от корня проекта.

В бизнес-сервисе фильтр разбирает только доверенные канонические заголовки, создаёт CurrentUser и Authentication. Некорректный/отсутствующий контекст на пользовательском маршруте — 401. @AuthenticationPrincipal не означает наличие JWT: principal построен из доверенного контекста.

Orchestrator проверяет актуальное членство/роль и передаёт CompanyScope в repository, каждый запрос ограничен организацией. PreProcessor проверяет право импорта через Orchestrator. Forecast получает ограниченный snapshot по внутреннему маршруту от Orchestrator, не произвольный доступ к БД.

Auth выпускает/обновляет токены и хранит сессии; gateway получает необходимые ключи проверки только для себя. Refresh обрабатывает Auth, его не пересылать бизнес-сервисам. Сетевые правила исключают прямой внешний доступ и недоверенных вызывающих. Для cookie API CSRF/Origin остаются на внешней границе.
