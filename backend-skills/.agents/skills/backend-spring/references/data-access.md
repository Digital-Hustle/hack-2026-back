# Данные и HTTP

Auth и Orchestrator владеют разными БД; права доступа к БД разделены. PreProcessor и Forecast используют HTTP DTO, без прямого SQL.

Таблицы Orchestrator: организации/членства, импорты/ошибки/операции/дневные остатки, категории/ручные исправления, планы/сопоставления с фактом, запуски прогнозов/дни/дефициты, запуски бэктеста/метрики. Это смысловая модель, названия таблиц проектируются в реализации.

Liquibase formatted SQL, применённые изменения неизменяемы, индексы под реальные запросы. Для данных организации запросы фильтруются по CompanyScope. Пример: select ... where company_id=:scope and date between :from and :to. Параметры, без строковой конкатенации. Учётные суммы numeric(19,2), даты date, моменты timestamptz. EOD не суммируется по строкам.

HTTP-адаптеры не держат транзакцию БД во время сети. У импортов устойчивый ключ идемпотентности, повторная загрузка не дублирует операции. Локальный статус/job сохраняется до/после вычисления явными шагами; сбой удалённого сервиса отражается состоянием и не подменяется успехом. Брокера нет. Межсервисные вызовы без JWT, с разрешённым контекстом и сетевыми ограничениями.

Бэктест сохраняет asOf, snapshot/knownAt, версию метода, параметры и метрики; новые планы не переписывают то, что было известно на исторической отсечке.
