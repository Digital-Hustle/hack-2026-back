# Backend: инструкции для агента

Это согласованный пакет инструкций текущего проекта, не исходники приложения. Пользовательские инструкции и правила среды имеют приоритет.

## С чего начать

Прочитать `.agents/skills/cashflow-architecture/SKILL.md`. Он задаёт архитектуру пяти сервисов и владение данными. Для Java-кода использовать `backend-spring`, для безопасности — `security-fintech` и `springboot-security`. Тестирование, отладка и подтверждение результата описаны в одноимённых навыках; читать по ситуации.

## Принятые решения

- Auth + Profile имеет собственную БД пользователей/сессий.
- Gateway валидирует JWT, удаляет токен и устанавливает доверенный контекст пользователя.
- PreProcessor без БД принимает CSV, парсит, нормализует, проверяет и категоризует.
- Orchestrator владеет отдельной БД организаций, операций, планов, прогнозов и метрик; проверяет права, запускает Forecast и отдаёт бизнес-данные фронту.
- Forecast без БД рассчитывает 30-дневный прогноз кодом, используя 8–12 недель истории, известные/регулярные платежи и накопление остатка. Историческая проверка — rolling-origin time-series cross-validation.
- Межсервисное взаимодействие — HTTP без JWT, защищённое сетью. Нет брокера, outbox/inbox и обязательного contract-first.
- Пока без CatBoost и других ML-моделей. Обоснованная вероятность разрыва не выводится из одного точечного прогноза.

## Инварианты реализации

Деньги BigDecimal/NUMERIC(19,2), строка в JSON. Факт и план разделены, один платёж не учитывается дважды. CompanyScope/права проверяются Orchestrator. JWT не пересылается между бизнес-сервисами. Клиентские заголовки идентификации заменяются gateway. Сетевые границы необходимо реализовать, а не только описать.

Секреты из окружения; персональные/финансовые данные и токены не логировать. Время через Clock. Применённые миграции не менять. Не утверждать, что код/тесты/развёртывание существуют или проверены, если это не подтверждено.
