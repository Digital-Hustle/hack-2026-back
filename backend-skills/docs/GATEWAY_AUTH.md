# Gateway и доверенный контекст

Основной источник: `.agents/skills/cashflow-architecture/references/gateway-and-patterns.md`.

Клиент → Gateway с JWT → проверка → замена заголовков идентификации → бизнес-сервис без JWT. Удалять Authorization/auth cookies перед отправкой в бизнес-сервис. Для Auth сохраняются необходимые code/verify/refresh/logout данные жизненного цикла сессии; refresh не уходит в остальные сервисы.

Сервисы не создают JwtDecoder/JWKS/resource server. Фильтр доверенных заголовков создаёт CurrentUser/Authentication для @AuthenticationPrincipal/@PreAuthorize. Orchestrator проверяет актуальное членство и роли компании, создаёт CompanyScope и фильтрует данные. Подмена companyId прав не даёт. Вызов PreProcessor проверяет доступ к организации через Orchestrator до обработки файла.

Gateway заменяет все входящие X-User-*/X-Auth-*, включая дубли/регистр, только затем устанавливает проверенный контекст. Межсервисные клиенты копируют только разрешённые поля контекста, без токена и полного Cookie. Безопасность доступа — закрытые порты и сетевые правила для разрешённых вызывающих, не секретный заголовок и не доверие любому участнику Docker-сети.

Внешний cookie API сохраняет CSRF/Origin-защиту. Внутренние endpoints извне не маршрутизируются. Тестировать неверный JWT на gateway, подмену заголовков, отсутствие токенов downstream, 401 без principal, 403 роли, 404 чужого ресурса, а также фактическую сетевую изоляцию.
