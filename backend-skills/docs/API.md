# HTTP-соглашения

- Внешний префикс `/api/v1/<service>/...`, gateway сохраняет согласованный путь. Внутренний `/internal/v1/...` закрыт извне и доступен разрешённым вызывающим по сети, без JWT.
- Пользовательский контекст создаёт Gateway; правила в docs/GATEWAY_AUTH.md.
- Деньги строкой с двумя десятичными знаками; даты YYYY-MM-DD, моменты ISO-8601 UTC; UUID для идентификаторов, camelCase в JSON, kebab-case в путях.
- DTO records, Bean Validation, общий ProblemDetail/ErrorCode. Неправильный формат — 400, отсутствие контекста — 401, запрещённая роль — 403, чужой/отсутствующий ресурс — 404, конфликт — 409, большой файл — 413, неподдерживаемый формат — 415, бизнес-валидация — 422, лимит — 429, недоступность зависимости — 503.
- Коллекции возвращать объектом items + метаданные. Пагинация ограничена по размеру и с устойчивой сортировкой.
- Импорт и повторяемые создающие запросы имеют устойчивый ключ идемпотентности; повтор не создаёт вторую операцию. Коррекции защищены версией записи от потерянных обновлений.
- Прогноз запускает Orchestrator, сохраняет входной snapshot и результат. Долгий импорт/бэктест может возвращать 202 и jobId; статус хранит Orchestrator, клиент опрашивает его. Это HTTP/таблица заданий, не брокер.
- Отдельные OpenAPI-контракты, генераторы клиентов и contract-first не обязательны. Поля HTTP-сообщений согласуются кодом и тестами; ручные суммы не числовой float.
- traceId/traceparent передавать для диагностики; не логировать тело финансовых запросов. Retry только с идемпотентностью/для безопасного чтения и ограниченным бюджетом.
